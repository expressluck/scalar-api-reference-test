Sample API Documentation

Docs API Reference

This sample is GitHub Pages compatible and uses distributed OpenAPI files. The docs follow a 3-level structure: Category → Sub-category → API.

How this is organized

  • Top level: Sales, Consumer
  • Second level: Customer, Item, Ledger Entry
  • Third level: Endpoint operations

Where to edit

  • docs/openapi/openapi.yaml (bundled render spec for Scalar)
  • docs/openapi/distributed-index.yaml (distributed $ref index)
  • docs/openapi/<category>/<sub-category>/openapi.yaml

Tip: open API Reference to view the Scalar-powered rendered UI.

API hierarchy

Sales
Customer
  • GET /sales/customers
  • POST /sales/customers
  • GET /sales/customers/{customerId}
Item
  • GET /sales/items
  • GET /sales/items/{itemId}
Ledger Entry
  • GET /sales/ledger-entries
  • GET /sales/ledger-entries/{entryId}
Consumer
Customer
  • GET /consumer/customers/me
  • PATCH /consumer/customers/me
Item
  • GET /consumer/items/recommended
  • POST /consumer/items/{itemId}/favorite
Ledger Entry
  • GET /consumer/ledger-entries/rewards
  • GET /consumer/ledger-entries/rewards/{entryId}

Distributed specs are kept per category/sub-category, and rendered through a bundled root spec for maximum portability.
